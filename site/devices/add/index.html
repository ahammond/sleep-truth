Supported devices

Add the next device

Sleep Truth draws from one device-neutral file. A new device needs two things: a way to download its data to the user's computer, and a converter into that file. The printout, markers, and print layout come for free.

1. Open an issue first

Open an issue on GitHub before writing code. Say:

  • which device, and the API or export it offers;
  • how a user signs in (OAuth, an API key, a file export);
  • whether it gives sleep stages per time step, and how long each step is;
  • whether its timestamps carry the local time zone offset.

Today the command-line tool is built around one device. Your pull request will need a way to choose the device, so agree on the shape in the issue.

2. Write the converter

Add a pure function in packages/core that turns the device's records into periods of the nights file. packages/core/src/oura.ts is the worked example. Each period has:

  • id: <device>:<the device's own id>;
  • start and end: local time with its UTC offset;
  • epoch_seconds and stages: one letter per 30-second step, W awake, R REM, L light, D deep;
  • native_epoch_seconds: only when the device's steps are longer than 30 seconds and you repeated each one to fill the 30-second steps, so the printout can say so;
  • movement: one digit per step, 0 none to 3 active, all 0 if the device has none;
  • totals: asleep and in-bed seconds, as the device reports them;
  • source_type: the device's own label for the period, kept as is.

The full contract is §5.2 of docs/design/week-grid-mvp.md, and parseNightsFile enforces it.

3. Download to the user's computer

Add the sign-in and download code in packages/cli. It must keep these promises:

  • Data goes from the device maker straight to the user's computer. No server, no relay, no middle man.
  • Downloads are cached under ~/.local/share/sleep-truth/, so forget deletes them.
  • forget also cancels the device's access where its API allows it.
  • Secrets stay in ~/.config/sleep-truth/, readable only by the user.

4. Test with made-up data

Never commit real health data, not even your own. Build synthetic records shaped like the device's real responses, and test the converter and the client against them. The client tests use a stub instead of the network. 

mise exec -- pnpm test
mise exec -- pnpm typecheck

5. Document it

  • Add a setup page at site/devices/<device>/index.html, like the Oura Ring page.
  • Add the device to the Supported devices list on site/index.html and on the Get started page.
  • The printout's subtitle names the device from the file. Add its printed name to DEVICE_NAMES in packages/core/src/render.ts.

6. Open the pull request

Link the issue. Include a PDF printed from synthetic data, and say which real nights you compared against the device's own app.

Sleep Truth shows data recorded by a consumer wearable. It is not a medical device, not a diagnostic tool, and not medical advice.
